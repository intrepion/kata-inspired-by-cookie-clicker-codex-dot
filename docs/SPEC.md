# Lantern Orchard specification
The user delegated all design decisions. No interactive interview occurred. Alternatives considered: bakery, tide-powered town, paper mill, constellation forge, and lantern orchard. Selected a warm nocturnal orchard with crafted lanterns and visible growth, combining tactile gathering with an automation workshop.

Gather glow by clicking or keyboard activation of the lantern. Recruit five progressively stronger producers at rising costs. Buy six one-time improvements that improve clicks, production or both. Reveal seven permanent achievements. At 5,000 run glow, rekindle: exchange the run for embers that permanently add 10% production and click strength each. Preview the exact reward and lost items; explicit confirm/cancel dialog. A canceled action changes nothing. Persist progress locally; earn up to four hours of production away. Reject malformed saves and unsupported versions; future clocks grant nothing. Values remain finite and bounded. Handle fast repeated actions atomically, avoid negative balances, and show useful fractional rates. Layout works with keyboard and small screens. No external services or assets.

Test seams selected under delegated authority: pure game commands, save decoding and time advancement. These are the domain boundary, independent of DOM. Actual Mac Chrome verification uses visible controls; accelerated prestige/offline states may be tested via domain fixtures but must be labeled separately.
